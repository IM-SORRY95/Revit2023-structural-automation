# 잭서포트 자동 생성

## 1. 기능 개요

구조 BIM 모델의 보, 기둥, 바닥 및 구조기초 형상을 분석하여  
설정된 업무 기준에 맞는 위치에 잭서포트를 자동 생성하는 Revit 2023 기능입니다.

본 기능은 단순히 일정 간격으로 객체를 배치하는 방식이 아니라 다음 조건을 함께 검토합니다.

- 대상 구조부재의 유형명
- 보 또는 기둥의 실제 형상
- 생성 위치의 하부 지지체
- 기존 벽체와 구조기둥의 점유 구간
- 동일 위치의 기존 잭서포트
- 하단 및 상단 높이
- 최하층과 그외층 판정
- 높이 구간별 데이터 입력 규칙
- 현재 활성 뷰의 색상 표시 기준

> 공개 저장소에서는 실제 회사 내부 부재 코드와 매개변수명을  
> `SPECIAL_BEAM`, `SIDE_MEMBER`, `COLUMN_SUPPORT` 등의 예시값으로 일반화했습니다.

---

## 2. 개발 배경

구조 BIM 업무에서 잭서포트 모델링은 다음과 같은 이유로 반복 작업이 많았습니다.

- 보마다 길이와 지지 조건이 다름
- 하부 바닥이나 기초 높이가 위치별로 다름
- 벽체와 기존 기둥이 있는 구간은 별도 판단 필요
- 슬래브 경계부에서는 생성점 바로 아래에 바닥이 없을 수 있음
- 동일한 XY 위치라도 층별 높이 구간이 다르면 별도 생성 필요
- 최하층과 일반층을 구분해 수량을 집계해야 함
- 생성 후 높이별 데이터와 색상 검토가 필요함

수작업으로 모델링할 경우 위치 확인, 높이 입력, 중복 검토 및 데이터 입력을 반복해야 했으며,  
업무 기준을 작업자가 개별적으로 판단하기 때문에 누락이나 일관성 차이가 발생할 수 있었습니다.

이에 따라 실제 업무 기준과 예외조건을 정리하고,  
생성형 AI를 활용하여 Revit API 기반 자동화 기능으로 구현했습니다.

---

## 3. 주요 기능

### 3.1 대상 부재 판정

대상 부재는 별도의 표준부재명 매개변수가 아니라  
요소 유형명의 마지막 `_` 뒤 문자열을 사용하여 판정합니다.

예시:

```text
STRUCTURAL_BEAM_600_SPECIAL_BEAM
→ 표준부재명: SPECIAL_BEAM
```

이 규칙을 이용해 설정창에서 등록한 부재명과 모델 요소를 비교합니다.

---

### 3.2 특수 보 잭서포트

특수 보는 설정된 표준부재명과 생성 비율을 이용해 잭서포트를 배치합니다.

예시:

```text
생성 비율: 0.25;0.75
→ 보 길이의 1/4, 3/4 위치에 생성
```

두 개의 대상 그룹을 별도로 관리할 수 있습니다.

- A 그룹: 대상 부재명과 생성 비율 설정
- B 그룹: 대상 부재명과 생성 비율 설정
- 같은 표준부재명은 두 그룹에 중복 등록하지 않도록 검증

특수 조건이 적용되는 보는 긴 측면에 접촉한 부재의 방향을 확인하여 배치 개수를 조정할 수 있습니다.

- 양쪽 측면 접촉: 측면별 지정 개수 생성
- 한쪽 측면 접촉: 접촉한 측면에 지정 개수 생성
- 측면 접촉 없음: 보 중심에 지정 개수 생성

---

### 3.3 특수 기둥 주변 잭서포트

설정한 문구가 구조기둥 패밀리명에 포함되면  
기둥 외곽 네 방향에 잭서포트를 생성합니다.

생성 위치는 다음 순서로 계산합니다.

1. 기둥의 실제 Solid 및 외곽 범위 계산
2. 기둥의 회전 방향 확인
3. 네 외곽면 중심 계산
4. 설정된 이격거리 적용
5. 네 위치에 잭서포트 생성

해당 기둥 주변의 네 개 잭서포트는 하나의 세트로 취급하여  
최하층 또는 그외층 분류 결과를 동일하게 적용합니다.

---

### 3.4 일반 보 하부 잭서포트

일반 보 하부에서는 기존 구조기둥과 벽체가 실제로 지지하는 구간을 먼저 계산합니다.

처리 순서:

1. 보의 시작점, 끝점 및 길이 계산
2. 보 하부에 닿는 구조기둥 구간 탐색
3. 보 하부에 닿는 벽체 구간 탐색
4. 서로 겹치는 점유 구간 병합
5. 점유 구간을 제외한 나머지 구간 계산
6. 남은 각 구간을 독립적으로 재계산
7. 설정 간격을 초과하는 구간에 잭서포트 균등 배치

예시:

```text
남은 구간 4m → 1개
남은 구간 7m → 2개
남은 구간 10m → 3개
```

보 상부에만 닿는 벽체나 기둥은 지지 구간으로 사용하지 않습니다.

---

## 4. 하부 지지체 탐색

잭서포트의 하단 높이는 생성점 아래에서 가장 가까운 하부 지지체의 상단을 사용합니다.

하부 지지체로 선택할 수 있는 객체:

- 바닥
- 설정된 표준부재명의 구조기초
- 층 분류에 사용하는 하부 표식 요소

탐색 과정:

```text
생성점 XY 확인
→ 아래 방향으로 수직선 생성
→ 바닥 및 구조기초 Solid와 교차 검사
→ 가장 가까운 상단 Z 선택
→ 잭서포트 하단 높이로 적용
```

단순 Bounding Box만 사용하는 것이 아니라 가능한 경우 실제 Solid 교차값을 사용합니다.

---

## 5. 슬래브 경계부 위치 보정

슬래브 경계부에서는 원래 생성점 바로 아래에 바닥이 없을 수 있습니다.

이 경우 설정에 따라 다음 방향을 단계적으로 탐색합니다.

- 보 진행 방향
- 보 진행 반대 방향
- 보 직각 방향 양쪽
- 대각 방향
- 전역 X·Y 방향

검색 거리와 간격은 설정창에서 지정할 수 있습니다.

예시:

```text
최대 검색거리: 300mm
검색 간격: 50mm
상단 높이차 허용: 100mm
```

후보가 여러 개이면 다음 기준으로 선택합니다.

1. 가장 가까운 검색 링
2. 가장 높은 유효 지지체
3. 방향 우선순위

설정에 따라 잭서포트 위치를 찾은 유효 지점으로 이동할 수 있습니다.

---

## 6. 하부 지지체가 없을 때의 대체 기준

특수 보 하부에서 바닥이나 구조기초를 찾지 못한 경우  
보 양단에 접촉한 구조기둥을 대체 기준으로 사용할 수 있습니다.

처리 방법:

1. 보 양쪽 끝의 구조기둥 탐색
2. 각 구조기둥의 실제 하단 높이 계산
3. 보 길이 방향 비율에 따라 두 높이 보간
4. 보간된 높이를 잭서포트 하단으로 사용

양쪽 기준 기둥이 모두 확인된 경우에만 적용합니다.

---

## 7. 패밀리 및 유형 처리

잭서포트 패밀리는 다음 우선순위로 결정합니다.

1. 사용자가 지정한 구조기둥 패밀리와 유형
2. 설정된 RFA 파일 자동 로드
3. 프로젝트에 이미 존재하는 잭서포트 유형
4. 사용 가능한 원형 구조기둥 유형을 복제하여 자동 생성

공개용 기본 RFA 경로:

```text
%AppData%\RevitStructuralAutomation\JackSupport\JackSupport.rfa
```

패밀리가 자동으로 로드된 경우 실제 패밀리명과 유형명을 다시 확인하여 설정에 반영합니다.

---

## 8. 생성 원인별 유형명

생성된 잭서포트는 생성 원인과 원본 부재명을 유형명에 포함할 수 있습니다.

예시:

```text
PORTFOLIO_JACK_SUPPORT_특수보_SPECIAL_BEAM
PORTFOLIO_JACK_SUPPORT_RC보하부_RC_BEAM
PORTFOLIO_JACK_SUPPORT_특수기둥_COLUMN_TYPE
```

이를 이용해 생성 결과를 원인별로 선택하거나 현재 뷰에서 임시 분리할 수 있습니다.

---

## 9. 중복 생성 방지

중복 판정은 단순 XY 좌표만 비교하지 않습니다.

다음 세 조건을 모두 만족할 때만 기존 잭서포트와 동일한 객체로 판단합니다.

1. XY 평면 거리가 허용오차 이내
2. 하단 높이 차이가 허용오차 이내
3. 상단 높이 차이가 허용오차 이내

따라서 같은 XY 위치에 있더라도 다음 경우에는 별도 잭서포트로 생성할 수 있습니다.

- 위층과 아래층의 높이 구간이 다름
- 아래층 상단과 위층 하단이 단순 접촉함
- 일부 높이 구간만 겹침

---

## 10. 구조기둥 생성 방식

구조기둥 인스턴스 생성 시 Revit의 높이 0 오류를 방지하기 위해  
상단 조건을 먼저 설정한 뒤 하단 오프셋을 적용합니다.

처리 순서:

1. 기준 레벨 결정
2. 상단 레벨 결정
3. 구조기둥 인스턴스 생성
4. 상단 구속조건 및 상단 오프셋 적용
5. 하단 레벨 및 하단 오프셋 적용
6. 문서 재생성
7. 실제 높이 확인
8. 데이터 및 색상 적용

계산 높이가 지나치게 작은 위치는 생성하지 않습니다.

---

## 11. 최하층 및 그외층 분류

최하층 분류는 다음 우선순위로 처리합니다.

```text
1순위: 사용자가 선택한 실제 최하층 레벨
2순위: 하부 표식 요소와 접촉하는지 확인
3순위: 표식 요소와 접촉하지 않으면 최하층
```

실제 최하층 레벨에 속한 잭서포트는  
하부 표식 요소와 접촉하더라도 최하층으로 우선 판정합니다.

입력 가능한 데이터 예시:

```text
분류 매개변수: SUPPORT_FLOOR_CLASS
최하층 값: 최하층
그외층 값: 그외층
```

수량 집계용 매개변수를 별도로 설정하면 다음과 같이 입력할 수 있습니다.

```text
최하층 잭서포트 → 최하층 수량=1, 그외층 수량=0
그외층 잭서포트 → 최하층 수량=0, 그외층 수량=1
```

---

## 12. 높이별 데이터 입력

생성된 잭서포트의 실제 높이를 mm로 계산하여  
설정된 높이 구간의 인스턴스 매개변수에 값을 입력할 수 있습니다.

예시:

| 최소 높이 | 최대 높이 | 매개변수 | 입력값 |
|---:|---:|---|---:|
| 0mm | 3,000mm | SUPPORT_HEIGHT_A | 1 |
| 3,000mm | 5,000mm | SUPPORT_HEIGHT_B | 1 |

구간 조건:

```text
최소 높이 이상
최대 높이 미만
```

정수, 실수 및 문자열 매개변수를 지원하며,  
입력 전 등록된 높이 규칙의 값을 0으로 초기화할 수 있습니다.

---

## 13. 표시 색상

생성된 잭서포트는 요소 재료를 변경하지 않고  
현재 활성 뷰의 요소별 그래픽 재지정을 사용하여 표시합니다.

지원 방식:

- 공통 색상
- 최하층·그외층 분류 색상
- 높이 구간별 색상
- 높이 규칙 불일치 경고 색상
- 특정 대체 기준으로 생성된 객체의 별도 외곽선

색상은 다음 항목에 적용됩니다.

- 투영선
- 절단선
- 표면 솔리드 채우기
- 절단 솔리드 채우기

다른 뷰에서는 원래 표시 상태로 보일 수 있습니다.

---

## 14. 기존 잭서포트 재판정

이미 생성된 잭서포트 전체를 다시 수집하여  
현재 설정 기준으로 데이터와 색상을 재적용할 수 있습니다.

제공 모드:

### 판정색상 일괄 적용

- 최하층·그외층 다시 판정
- 높이 구간 다시 판정
- 데이터 매개변수 다시 입력
- 선택한 분류 기준의 색상 적용
- 오류 및 처리 수량 집계

### 공통색상 일괄 적용

- 층 분류와 높이 판정을 색상에 사용하지 않음
- 모든 기존 잭서포트에 같은 색상 적용

---

## 15. 생성 원인별 선택 및 임시 분리

유형명에 저장된 생성 원인을 기준으로 다음 기능을 제공합니다.

- 특수 보 잭서포트 선택
- 일반 보 하부 잭서포트 선택
- 특수 기둥 주변 잭서포트 선택
- 일반 기둥 주변 잭서포트 선택
- 생성 원인 정보가 없는 기타 잭서포트 선택
- 현재 뷰 임시 분리
- 임시 분리 원복

옵션창을 닫지 않아도 Revit 모델에서 선택 결과를 확인할 수 있습니다.

---

## 16. 모델리스 옵션창과 ExternalEvent

설정창은 모델리스 방식으로 구성되어  
창을 열어 둔 상태에서도 Revit 모델을 탐색할 수 있습니다.

Revit API를 직접 실행하지 않고 다음 흐름으로 처리합니다.

```text
설정창 버튼 클릭
→ 요청 종류 저장
→ ExternalEvent 발생
→ Revit API 컨텍스트에서 요청 실행
→ 결과창 표시
```

요청 종류:

- 자동 생성
- 판정색상 일괄 적용
- 공통색상 일괄 적용
- 모델에서 선택
- 현재 뷰 임시 분리
- 임시 분리 원복

다른 모델이 활성화된 경우 잘못된 문서에서 작업하지 않도록  
옵션창을 열었던 문서와 현재 활성 문서를 비교합니다.

## 23. 제한사항

- 공개용 코드는 포트폴리오 목적의 재구성본입니다.
- 실제 회사 내부 부재 코드와 매개변수명은 포함하지 않습니다.
- 실제 RFA 패밀리와 프로젝트 모델은 제공하지 않습니다.
- 일부 클래스는 서로 의존하므로 단일 파일만으로 실행할 수 없습니다.
- 프로젝트별 패밀리 구조와 모델링 방식에 따라 설정 조정이 필요합니다.
- 곡선 보와 비정형 패밀리는 추가 검증이 필요할 수 있습니다.
- 전체 Revit 2023 프로젝트 참조를 포함한 공개용 컴파일은 별도로 검증해야 합니다.
